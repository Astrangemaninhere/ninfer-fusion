## 2. 三条硬结论

1. **KV 载荷与档位几乎无关**（bf16/int8/fp8/nvfp4/iso3 全为 17792 B/token，e8 17408，−2.2%），
   且随 max-context 线性（65K→262K 时 1112→4448 MiB）。=> 当前引擎**不因降档而放大上下文
   容量**；"降档换容量" 在 qwen3.8-27b 上不成立（与 README/VRAM.md 的 E8Kv≈减半矛盾，
   需查 page slot 是否按最大档固定）。速度差异也在 ±5%（27B 权重带宽主导）。
2. **e8 只在前 8 个全注意力层可用**：`8-15:e8` / `all:e8` / `0-11:e8` 针刺 **0/8**（静默错误，
   不报错不崩），而 `0-7:e8` 及任何 "e8 限层 0-7 + iso3/int8 补上层" 的组合都是 **8/8**。
   建议：引擎侧对 e8 层做几何校验并显式拒绝，或在 `kv_bit_budget.py` 用 `--e8-layers` 限层
   （默认 8）。
3. **纯档位之间质量无差异**：bf16/int8/nvfp4/iso3 全部 6/8 且缺的针相同（YPP63F/KRZJ6K）。
   针刺在 32K 不足以区分 4bit 档位质量——需要 PPL（`ninfer-perplexity` 只支持
   bf16/int8/fp8）或更长上下文/更硬探针来建立质量阶梯。

## 3. 位预算分配器（给定 bit，含小数）

`tools/archkit/kv_bit_budget.py`：DP 精确解 `min 质量罚分 s.t. Σbits ≤ B·L`，输出
`--kv-layer-storage` 表。位成本：bf16 16.0 / int8 8.25 / fp8 8.03 / nvfp4 4.50 / e8 4.06 /
iso3 3.00；质量罚分先验：bf16 0 / int8 0.02 / fp8 0.03 / e8 0.08 / nvfp4 0.30 / iso3 0.50
（**先验，待 PPL 校正**）。

16 层示例（`--layers 16`，e8 限前 8 层）：

| 目标 B | 实际 | 表 |
|---|---|---|
| 3.5 | 3.46 | `0-6:e8,7-15:iso3` |
| 4.0 | 4.00 | `0-7:e8,8-12:nvfp4,13-15:iso3` |
| 4.5 | 4.42 | `0-7:e8,8:int8,9-14:nvfp4,15:iso3` |
| 5.0 | 4.98 | `0-7:e8,8-10:int8,11-15:nvfp4` |
| 6.0 | 5.92 | `0-7:e8,8-14:int8,15:nvfp4` |
| 8.0 | 7.99 | `0:e8,1-15:int8` |
| 16.0 | 16.00 | `0-15:bf16` |

## 4. 按设备定策略（框架就绪）

矩阵脚本把设备名写进 CSV 头（`# device=...`）。换设备只需在目标机上重跑
`_kv_matrix_v3.sh` / `_kv_quality.sh` 并把 CSV 追加成一张跨设备表；分配器的质量罚分表
按设备替换即可。**本机只有一张 5090 D**，其它设备（V100/4090/3090 等）待有机器时补跑。

## 5. 复现

```
# 速度+载荷+质量矩阵
bash _kv_matrix_v3.sh                     # 产出 /home/user/kv_matrix_v3.csv
# 干净质量排序（32K/8 针）
bash _kv_quality.sh                       # 产出 /home/user/kv_quality.csv
# e8 层边界定位
bash _e8_probe.sh                         # 8-15:e8 -> 0/8, 0-7:e8 -> 8/8
# e8+iso3/int8 混搭
bash _e8_iso3.sh                          # 三组均 8/8
# 位预算表
python tools/archkit/kv_bit_budget.py --layers 16 --bits 3.5 4 4.5 5 6 8 12 16
```
