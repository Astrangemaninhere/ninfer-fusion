## 2. Fetch path (requirement 2)

`fault(span_id)`: mmap source → `memcpy` into injected pinned staging (byte-exact
mirror; engine injects `cudaHostAlloc(mapped)` — one line at the consumer) → consumer
enqueues `cudaMemcpyAsync(pinned, device_slot, stream)` (P1, one line). LRU + epoch
exemption as PleTable. **Exception safety found by my own check**: the first version
allocated before evicting, so a budget-exhaustion throw left the cache over budget with
the span resident; fixed to `make_room(incoming)` FIRST (throw before any allocation,
failed fault leaves state unchanged) + deterministic use-sequence LRU (unordered_map
iteration order made ties arbitrary). 10/10 checks now pass (below).

## 3. Hot-path hook — SPECIFIED, not touched (requirement 3)

- **Hook point**: weights resolve through `MaterializedArtifact::device_data(handle)`
  (`materializer.cpp:70`) at bind time. P1 design: resident weights keep arena
  pointers; offloaded weights get a **FIXED device page slot in a separate bounded page
  arena** — the bound pointer NEVER changes, so there is no per-GEMM pointer chase. The
  GEMM entry calls `ensure_resident(span_id, stream)`.
- **Per-GEMM cost**: steady state (working set fits the page arena) = one atomic
  residency-bit read + branch, lock-free; miss = mutex + make_room + memcpy +
  `cudaMemcpyAsync` (ms-scale, amortized by LRU). Thrashing regime = one H2D per use —
  measurable, never silent.
- **Locking**: hit path lock-free because slot pointers are stable — PleTable's
  lock-free current-gather exemption is the precedent and transfers directly; eviction
  skips entries whose last fault epoch == the current epoch, and the P1 launcher closes
  the epoch on the stream event after kernel completion (the one synchronization
  decision P1 must make; flagged, not decided here).
- **Load-time consumer** (P1, file:line): `materializer.cpp:125` loop over
  `plan.device_objects` — offloaded objects skip `device_arena_->alloc_bytes` and
  register their mmap span in the page cache; `device_capacity_bytes` shrinks by the
  offloaded bytes (binder.cpp plan computation).

## 5. Budget interaction (requirement 5)

**Two separate budgets**: `cold_host_bytes` stays scoped to the KV cold tier;
`weight_host_offload_bytes` is W13's. Rationale: disjoint lifetimes (KV cold pages age
per request; weight spans are static after load) and disjoint failure modes; a shared
pool would let KV pressure evict weight staging invisibly. Exhaustion semantics:
pinned LRU eviction = NORMAL (bandwidth only, never precision — byte mirrors);
span > whole pinned budget → throw at registration; fault with only in-flight spans
evictable → throw (loud); P1 device page-arena exhaustion → throw with span id.
Never a silent precision change.
