**机制根因（两条，均已用仓库内三方证据交叉验证）**
- **M1 目标行 off-by-one**：引擎要 `ids16[a+s]`（= `--target-shift 0`），`train_dflash2.py` 默认给 `ids16[a+1+s]`（= shift 1）。

  mask 口径命中率比真 token 口径低 **5.5×**（step1200：0.031 vs 0.171），step400 时为 **0/679**。

## 3. 引擎侧"需求"的证据链（file:line，只读代码）

1. **草稿块构造**：`include\ninfer\ops\prepare_masked_block.h:20-27`
   `ids[0]=anchors[b]`（锚点 token）、`ids[i]=mask_id (1≤i<W)`、`positions[i]=lengths[b]+min(i,V-1)`。
2. **引擎调用点**：`src\targets\qwen3_6\impl\runtime\dflash2_impl.h:192-196`
   `prepare_masked_block(anchors, frontiers, attention_valid, Config::mask_token, …)` → `ops::embedding(ids)`；
   `:306-319` 注释 **"DFlash2 predicts the seven masked columns (1..7)"** ⇒ 草稿 = 列 1..7，列 0 是 bonus/query。
3. **接受规则**：`src\ops\kernel\speculative_round.cuh:18-37`
   `verify_ids[0]=anchor, verify_ids[j]=drafts[j-1]`，`positions[j]=base_positions[j]+j`；
   `:131-141` 贪心快路径 `while (a<extent && row_targets[a]==row_drafts[a]) ++a;`
   ⇒ drafts[s] 必须等于"它在 verify 里占的那一列的下一 token 预测"，即 `verify_ids[s]`（=锚点当 s=0）位置的 next-token。
4. **位置基准**：`src\targets\qwen3_6\impl\runtime\program_impl.h:11822-11827`（普通解码）
   `tokens = ledger.back()`，`cache/rope_positions = frontier` ⇒ **`execution_frontier` = 最后一个已提交 token 的 index**（不是 count；否则普通解码会整体错位一位）。由 `:12383-12402` 的 dflash2 ingress 用同一 `frontier` 喂 `prepare_masked_block`。
5. **结论（离线口径）**：anchor = `tokens[a]`（位置 a），草稿槽 s 位于位置 a+1+s，必须产出**位置 a+1+s 的 token**，其教师行 = `ids16[a+s]`（因为 `ids16[t]` 预测 `t+1`，§2 实证）⇒ **引擎需求行 = `ids16[a+s]`（= `--target-shift 0`）**。
6. 常量（`src\targets\qwen3_6_27b\impl\config.h:111-139`）：`block_drafts=7`、`mask_token=248070`、`local_window=2048`、`target_feature_layers={5,19,33,47,61}`（与 `train_dflash2.py:43` 一致）。

**仓库内参考训练器同口径（两条独立证据）**
- `dl\aeon-train_head.py:25-42`：block 位置 1..B-1 **填 mask**，"matches spec_generate exactly … teacher-forcing … is **NOT recommended (train/inference skew + label leak)**"；
  `:54-60`：块位置 p 预测 `x_{a+p}`，教师 = 目标在 **a+p-1** 的 next-token 分布 ⇒ 行 index **a+p-1** = shift 0 ✓。
- `train_dspark.py:417-432`：`block_ids=full(MASK); block_ids[r,0]=tok[a]`（anchor+mask ✓）、`teacher_src[r,p-1]=a+p-1`（shift 0 ✓）。
- `train_dflash2.py:430-436`：`block = tok[a:a+B]`（**真 token** ✗）+ `ids16[a+args.target_shift …]`（默认 **shift=1** ✗）。

## 5. Q1：位置 0 的"上限"

把 §4 的 slot0 单独拎出来（答案键 = 教师 top-1 `ids16[a,0]`）：

| ckpt | tf（训练器输入） | mk（引擎真实输入） | shift1 行 `ids16[a+1,0]`（tf） |
|---|---|---|---|
| step_000400 | 0.0501 | 0.0000 | 0.0604 |
| step_001200 | **0.1708** | **0.0309** | 0.2504 |
| step_001800 | 0.1222 | **0.0427** | 0.2047 |

- **按引擎真实输入（mask 块）**：位置 0 上限 = **3.1%–4.3%**（step1200/1800）；step400 是 **0/679**。

|---|---|---|---|---|---|
| mk / eng（引擎口径） | 0.0000 | 0.0309 | 0.0427 | ≈ +0.126 /nat | **≈ 0.10** |
| tf / leg（对自己最有利） | 0.0604 | 0.2504 | 0.2047 | ≈ +0.73 /nat（用 400→1200 两点） | **≈ 0.66** |

- 到地板的**步数**（按近期斜率）：(1.847−1.365)/3.3e-4 ≈ **+1460 步** ⇒ 约 step 3300/7900（约 2 小时 @0.2 step/s，step=4 文件×12 anchors=48 样本）。
- **量化结论**：按当前配方，即便 loss 训到"完美"（= 教师熵地板），外推的位置 0 命中率也只有 **≈0.10（引擎口径）/ ≈0.66（最有利口径）**，**到不了 0.9**；换算式说，要 0.9 需要 CE ≈ 0.95 < 地板 1.365 ⇒ **在当前配方下不可达**（这是 2–3 点线性外推的估计，非实测；非线性/噪声会改变数值，但"接近地板仍远低于 0.9"的方向稳健）。
- 另需注意 ckpt 1200→1800 的**非单调**：tf/leg 0.250 → 0.205、tf/eng 0.171 → 0.122（mk 略升 0.031→0.043）⇒ 命中率不是 loss 的单调函数，"继续训"未必线性换命中率。
- 其它杠杆（供排序，非本次实测）：① 先修 M1+M2（改一行 mask 块 + 换目标行）；② 每步样本量（现在 48/步；语料全量约 70 万位置，step1900 时累计 ≈9.1 万样本 ≈ 13% 一个 epoch）；③ 目标本身（top-16 截断的 CE 地板就是教师熵，"要 argmax 就要换/加 argmax 型监督，或降温目标"）。

## 8b. 附加探针：上下文宽度（引擎 2048 vs 训练 128）与主干 dtype

**上下文宽度**（同一 60 anchors、同一 ckpt step_001200、mk 模式、bf16 主干；`_collab\A2_ctx_probe.log`）

| ctx | `eng` slot0 | `eng` 非0槽均值 | `leg` slot0 | `in16_eng` slot0 | `eng` 计数 slot0 |
|---|---|---|---|---|---|
| 128 | **0.0167** | 0.112 | 0.0333 | 0.0333 | 1/60 |
| 512 | **0.0833** | 0.053 | 0.0333 | 0.1000 | 5/60 |
| 2048（= 引擎 `local_window`） | **0.1333** | 0.071 | 0.0833 | 0.1667 | 8/60 |

⇒ 在引擎真正的工作点（ctx=2048）上，mask 口径的位置 0 命中率是**训练/我主表所用 ctx=128 的 8 倍**（8/60 vs 1/60），且已回到 tf@128 档（0.117）的量级；`in16` 软指标同向（0.033→0.100→0.167）。
两条含义：① **§4/§5 主表的 ctx=128 数字对引擎是保守下界**，不是引擎的真实工作点；② 这同时**部分解释**了引擎接受率（4.5%/41.8%）高于我 128-ctx 离线值 —— "更长上下文有用"这条从"未知"变成"有指示性证据"（n=60，链的逐槽样本更小，别外推太远）。
③ 训练用 ctx=128 而引擎给 2048，本身又是一条 train/inference skew（M2 的同类），值得在 §10-1 的 A/B 里一并扫 ctx。

**主干 dtype 对拍**（同 60 anchors，fp32 trunk vs bf16 trunk，`_collab\A2_dtype_fp32.log` vs `A2_ctx_probe.log` ctx=128 段）
`tf`：`eng` slot0 0.1167 vs 0.1167、`leg` 0.1667 vs 0.1667（逐槽完全相同）；`mk`：`eng` slot0 0.0167 vs 0.0167，仅非 0 槽个别差 1/60（如 slot2 leg 0.0833 vs 0.0667）⇒ **数值敏感性可忽略**（≤1 样本/槽）。
